# 麦麦领券助手 mcd-coupon-helper

> 一个跑在 WorkBuddy 里的麦当劳优惠券管家：**一键领券 → 核对到账 → 盘券包 → 算真实省多少**。
> 基于麦当劳中国官方 MCP（`mcd-mcp`）开发，是麦当劳程序员节创意开发大赛参赛作品。

---

## 为什么做这个

麦当劳的券不是「领了就好」，中间有三道真实的坎，这个 Skill 就是专门来填这三道坎的：

| 坎 | 实际情况 | 本项目的处理 |
|---|---|---|
| **领了不一定到账** | 实测领 3 张，券包只 +2 张，接口却报「成功 3 张、失败 0 张」 | 强制双向核对（券状态 + 券包张数），差几张、差哪张，直接指出来 |
| **拿到手不知道该用哪张** | 券的可用性被「日期区间 × 星期限定 × 每日时段」三重约束，早餐券常常只有 05:00–10:29 一个窗口 | 解析器按三重约束逐张判定「此刻能不能用」，不是只看日期 |
| **说得出「省多少」的工具很少** | `query-my-coupons` 只是资产列表，不校验门店/订单能不能用 | 门店可用券 + 算价接口双算（带券/不带券各一次），给出真实实付与差额 |

一句话：**它不只告诉你有什么券，还告诉你哪张现在能用、用了能省多少钱。**

## 目标用户

- **每天早上想吃早餐、但总错过早餐券时段**的上班族（早餐券窗口极窄，睡过头就没了）
- **手里攒了十几张券、懒得逐张看规则**的重度用户
- **公司团餐/下午茶采购**，需要判断「用哪张券、凑到哪一档最省」的人
- **想基于麦当劳 MCP 二次开发**的开发者，需要一份实测过的接口避坑指南（见 `MCP_INTEGRATION.md`）

## 安装方法

### 方式一：装进 WorkBuddy（推荐，5 步）

1. 申请麦当劳 MCP Token（活动官方渠道发放）
2. 打开 WorkBuddy → 左侧边栏【专家·技能·连接器】→【连接器】页签
3. 右上角【自定义连接器】→【配置 MCP】，填入 `mcp-config.example.json` 的内容，把 `${MCD_MCP_TOKEN}` 换成你的真实 Token
4. 把本仓库的 `SKILL.md` 放到 `~/.workbuddy/skills/mcd-coupon-helper/SKILL.md`（Windows 为 `C:\Users\<你>\.workbuddy\skills\mcd-coupon-helper\SKILL.md`）
5. 在对话里说「麦当劳领券」即可触发

> Token 与你的麦当劳会员账号绑定，**属于敏感凭证**。本仓库只提供环境变量占位符，不含任何真实 Token。

### 方式二：只用解析器（不装 WorkBuddy）

券包接口返回的是 Markdown 文本，`scripts/parse_coupons.py` 可以把它变成结构化 JSON，方便接进你自己的程序：

```bash
python3 scripts/parse_coupons.py fixtures/coupons_sample.md
python3 scripts/parse_coupons.py --now "2026-10-19T08:00:00" fixtures/coupons_sample.md
```

纯标准库实现，无第三方依赖，Python 3.8+。

```bash
python3 -m unittest discover -s tests -v   # 19 个测试，含 4 种有效期格式与可用性判定
```

## 使用示例

### 示例 1：一键领券并核对到账

> **你**：帮我领券
> **Skill**：先查 `available-coupons`，再调 `auto-bind-coupons`，最后交叉核对。

```
领券完成：接口报成功 3 张、失败 0 张

| 券名 | 用券价 | 有效期 | 场景 |
|---|---|---|---|
| 9.9元中杯冰美式 | ¥9.90 | 10-19 00:00 ~ 10-25 23:59 | 到店/外送 |
| 人气麦旋风买一送一 | ¥15.00 | 10-19 00:00 ~ 10-25 23:59（10:00-22:00） | 到店 |

⚠️ 到账核对：券包实际只新增 2 张（5 → 7），「免费脆薯饼」领取成功但未出现在券包，
建议到麦当劳 APP「我的卡券」里确认。
```

注意最后这行——这是真实发生过的差异，Skill 不会用「已全部领取」糊过去。

### 示例 2：盘券包，按紧急度分档

> **你**：我有哪些券快过期了

```
今日到期（1 张）
| 券名 | 用券价 | 可用时段 | 场景 |
|---|---|---|---|
| 火腿扒堡早餐两件套 | ¥9.90 | 10-19 05:00 ~ 10:29 | 到店 |

3 日内到期（2 张）
| 芝香脆鸡扒堡早餐两件套 | ¥9.90 | 10-20 05:00 ~ 10:29 | 到店 |
| 高达芝士蛋堡早餐两件套 | ¥9.90 | 10-21 05:00 ~ 10:29 | 到店 |

稍后可用（4 张）
...
```

三张早餐券正好排在周一、周二、周三，**每天只有一个 5.5 小时窗口**，这是券包里最容易被浪费的一类。

### 示例 3：算用券能省多少

> **你**：我今天想喝冰美式，用券能省多少？

Skill 会先确认门店营业中（打烊时算价接口直接返回 `60003`），再对同一份餐品算两次价：

```
原价 ¥30.00 → 用券 ¥9.90 → 省 ¥20.10（67%）
券：9.9元中杯冰美式  有效期 10-19 ~ 10-25 全天  适用：到店/外送
```

### 示例 4：解析器输出（给开发者）

```json
{
  "name": "11.9元麦辣鸡腿堡",
  "coupon_price": 11.9,
  "validity": {
    "valid_from": "2026-10-19 10:30",
    "valid_to": "2026-10-23 23:59",
    "weekdays": [0, 1, 2, 3, 4],
    "daily_window": "10:30-23:59"
  },
  "received_at": "2日前收到",
  "tags": ["到店专用", "外送专用"],
  "channels": ["到店", "外送"],
  "expiring_today": false,
  "usable_now": false,
  "days_left": 4
}
```

`weekdays: [0,1,2,3,4]` 表示周一至周五可用（周一=0）。周六 12:00 拿这张券去算价，`usable_now` 会是 `false`——**只看日期的实现会在这里出错**。

## 能做什么 / 不能做什么

| 能做 | 做不到，以及原因 |
|---|---|
| 查可领券、一键领券、核对到账 | 不能自动下单——本 Skill 明确不触碰交易 |
| 盘点券包、按到期时间分档 | 拿不到已持有券的 `couponId`——接口只在**领券那一刻**返回它，`query-my-coupons` 不返回，丢失后无法找回 |
| 解析 4 种有效期格式与可用时段 | 没有「批量算哪张最省」的接口，只能逐张传 `couponId` 试算，券多时较慢 |
| 门店可用券 + 算价给出真实省额 | 算价必须在营业时段内，打烊返回 `60003`；领券则不受营业时间限制（适合做定时任务） |

## 实测基础

本项目的规则不是照文档抄的，而是把 `mcd-mcp` 的 35 个工具实测了 16 个之后写成的，所有「已知坑」都对应一次真实失败：

- `available-coupons` 无券时会抛协议错误（`data must be array`），不能当成「没券」
- `query-store-coupons` 返回空数组有两种原因：门店没券 / 门店没营业，必须二次判定
- 券接口返回的全是 Markdown 文本，含 `<img>` 标签，需要正则清洗
- 同一门店、不同业务场景（到店/外送/团餐）的 `beCode`、SKU、价格是三套独立体系

完整实测记录见 `MCP_INTEGRATION.md`。
