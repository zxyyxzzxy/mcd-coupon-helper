# 场景 A / B：查可领券 与 一键领券

> **何时读本文件**：用户说「有什么券可以领」「帮我领券」「一键领券」「麦麦省」。
> **不适用**：问已持有的券走 `coupon-wallet.md`；问某门店能用哪张券走 `coupon-price.md`。

---

## 场景 A：查可领券

调 `available-coupons`（无参数）。

输出：

- 表格，按状态分组：先「可领取」，后「已领取」
- 每行：券名、状态
- 末尾一句结论：还有 N 张可领，可直接说「帮我领券」

若返回 MCP 错误（`data must be array`），说明当前拿不到券数据，告知「暂时查不到券列表，可能是服务波动」并建议稍后重试。**不要**把它当成「没有券可领」的确定结论。

---

## 场景 B：一键领券（必须双向核对）

1. 调 `available-coupons`，统计状态为「可领取」的张数。
2. 为 0：告知「当前没有可领的券」，结束，**不调**领券接口。
3. 否则调 `auto-bind-coupons`（无参数，一次领完全部）。
4. 解析返回：`总计 / 成功 / 失败`，以及每张成功券的 `名称` + `couponId` + `couponCode`。
   - **务必保留 `couponId` 与 `couponCode`**：这是后续算价的唯一切入点，`query-my-coupons` 不返回它们，丢失后无法找回。
5. 核对（关键）：
   - 再调 `available-coupons`，确认原「可领取」项已变「已领取」
   - 调 `query-my-coupons`，比对新增张数是否等于「成功」数
6. 输出成功/失败数、每张券的名称与有效期；**若到账数少于成功数，单独一行指出哪张没到账**。

示例输出：

```
✅ 领券完成：接口报成功 3 张、失败 0 张

| 券名 | 用券价 | 有效期 | 场景 |
|---|---|---|---|
| 9.9元中杯冰美式 | ¥9.90 | 10-19 00:00 ~ 10-25 23:59 | 到店/外送 |
| 人气麦旋风买一送一 | ¥15.00 | 10-19 00:00 ~ 10-25 23:59（10:00-22:00） | 到店 |

⚠️ 到账核对：券包实际只新增 2 张（5 → 7），「免费脆薯饼」未出现在券包，
建议到麦当劳 APP「我的卡券」确认。
```

---

## 铁律

1. **不要只信「成功」计数。** 实测出现过接口报成功 3 张、券包只 +2 张的情况，且此差异会跨天持续存在。
2. **领券不受营业时间影响**，凌晨也能领；这一点与算价不同，别混。
3. **失败数为 0 不等于全部到账**，以券包张数为准。
