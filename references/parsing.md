# 数据解析手册

> **何时读本文件**：解析券有效期、判断「此刻能不能用」、核对字段可靠性、需要判断门店是否营业时。

---

## 一、券有效期：四种格式

| 格式 | 样例 | 解析要点 |
|---|---|---|
| 跨日 + 星期 + 时段 | `2026-10-19 10:30-2026-10-23 23:59 周一、二、三、四、五 10:30-23:59` | 起止日期 + 生效星期 + 每日时段，三者同时约束 |
| 纯日期区间 | `2026-10-19 00:00-2026-10-25 23:59` | 全天可用 |
| 单日 + 星期 + 时段 | `2026-10-19 05:00-2026-10-19 10:29 周一 05:00-10:29` | 典型早餐券，当天当段过期 |
| 跨日 + 时段（无星期） | `2026-10-19 00:00-2026-10-25 23:59 10:00-22:00` | 每日限时段 |

判断「今天能不能用」必须同时满足：**今天在日期区间内** 且 **星期匹配** 且 **当前时刻在时段内**。

只看日期是最常见的错误。例如 `11.9元麦辣鸡腿堡` 限定周一至周五，周六拿着它去算价一定失败。

## 二、字段可靠性

| 字段 | 来源 | 可靠性 |
|---|---|---|
| 券名、用券价、有效期、标签 | `query-my-coupons` | 稳定 |
| `couponId` / `couponCode` | 仅 `auto-bind-coupons` 返回 | 稳定，但只在领券那一刻给出 |
| 券是否「可领取」 | `available-coupons` 状态字段 | 稳定 |
| 券的适用商品清单 | `query-store-coupons` 的 `products[]` | 需门店 + 营业时间 |
| 单张已持有券的 `couponId` | 无接口返回 | **拿不到**，不要编 |
| 积分字段 | `query-my-account` | 稳定，但值是**字符串**，需转数字 |
| 积分商品 | `mall-points-products` | 含已下架商品，需按 `downTime` 过滤 |

## 三、门店营业状态

- `query-nearby-stores` 返回 `businessStartTime` / `businessEndTime`（如 `07:30` ~ `00:00`）
- 跨零点门店（`businessEndTime` < `businessStartTime`）按跨日区间判断
- 打烊时 `calculate-price` 报 `60003 门店暂停营业`
- 领券、查券包、查积分**都不受营业时间影响**，只有算价受限

## 四、展示清洗

券接口返回的 Markdown 含 `<img src="巨长签名URL">`。展示时：

- 不要原样吐 `<img>` 标签给用户
- 不要把签名 URL 抄进回答里
- 需要图片时由前端渲染，文本里只保留券名
