# 已知坑（均为实测结论）

> **何时读本文件**：接口报错、返回空、数量对不上、结果反直觉时，先来这里比对。

---

| # | 现象 | 真实原因 | 正确处理 |
|---|---|---|---|
| 1 | `available-coupons` 抛 `Structured content does not match the tool's output schema: data/data must be array` | 无券或服务波动时返回结构不符合自身 schema | 当作**可重试的临时故障**，重试一次；仍失败就说「暂时查不到」，不要断言「没有券」 |
| 2 | 领券接口报「成功 3 张」，券包只 +2 张 | 发券与入包异步，个别券未到账 | 双向核对并以券包张数为准，指出哪张没到账 |
| 3 | `query-store-coupons` 返回 `[]` | 可能是门店真没券，也可能是**门店打烊** | 先看营业时间，再判断 |
| 4 | `calculate-price` 返回 `60003` | 门店暂停营业 | 停止算价，提示营业时段 |
| 5 | 券接口返回的不是 JSON | 接口面向大模型，返回 Markdown 文本 | 按 `parsing.md` 解析，不要假设 JSON |
| 6 | 部分券没有「领取时间」字段 | 字段非必返 | 按可选处理，缺失留空 |
| 7 | 已持有的券查不到 `couponId` | 该字段只在领券返回中出现 | 如实说明无法带券算价，不编造 |
| 8 | 团餐场景报 `60006 商品已售罄或不可售` | 到店/外送/团餐是**三套 SKU** | 按场景重新取菜单，`productCode` 不跨场景复用 |
| 9 | 积分商城里有早已下架的商品 | `status` 仍为上架，但 `downTime` 已过 | 用当前时间比对 `downTime`，剔除后再展示 |
| 10 | `campaign-calendar` / `query-my-coupons` 只返回人读文本 | 接口设计如此 | 不要试图强解析成结构化字段；需要结构化就用仓库里的 `parse_coupons.py` |

## 遇到新坑时

先确认是「接口问题」还是「我的解析问题」，两者处理方式完全不同：

- 接口返回结构异常 → 重试一次，记录原样返回
- 解析结果不对 → 检查有效期格式是否属于 `parsing.md` 里的四种之一，若是新格式，按新格式补规则
